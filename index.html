A new way to write C#

C# 終於可以像 Python 一樣，從一個檔案開始。

.NET 10 的 File-based Apps，不只是少了一個專案檔。它改變的是 C# 被拿起來使用的方式。

當一門語言不再要求你先搭好鷹架，它才真正有機會走進臨時工具、自動化與 AI Agent 的日常。

少掉的不是 .csproj，而是開始之前的心理成本。

過去談到 C#，人們往往先想到解決方案、專案、SDK 設定與完整的工程結構。這些東西在大型系統裡很重要，卻也讓一段原本只需要十行的程式，必須先經過一整套儀式。

.NET 10 的 File-based Apps 把那道門檻拆掉了。現在，你可以建立一個 .cs 檔案，寫下頂層陳述式，然後直接執行。它仍然是經過編譯的正式 .NET 應用程式，只是開始的方式變得更輕。

真正重要的不是「C# 變成腳本語言」，而是 C# 終於允許你先寫，再決定要不要長成一個專案。
01

從一行開始，保留長成系統的可能。

最小範例沒有任何樣板。這種輕量，才是 File-based Apps 真正的價值。

hello.csC#
Console.WriteLine("Hello from C# File-based Apps! 🚀");
TerminalRun
dotnet hello.cs
# Hello from C# File-based Apps! 🚀

安裝 SDK

使用 .NET 10 SDK，確認版本為 10.x。

建立檔案

新增一個 .cs 檔，直接使用頂層陳述式。

直接執行

使用 dotnet app.cs，不必先建立專案。

02

它不是玩具，而是一個完整的入口。

命令列參數、NuGet 套件、Minimal API，都能從同一個單檔模型開始。

命令列參數

快速建立一次性 CLI 與資料處理工具。

NuGet 套件

直接在檔案頂端宣告依賴，不必先手動建置專案。

Minimal API

一個檔案也能成為可執行的 Web API。

greet.csArguments
var name = args.Length > 0 ? args[0] : "World";
Console.WriteLine($"Hello, {name}!");
console.csNuGet
#:package Spectre.Console@*

using Spectre.Console;

AnsiConsole.MarkupLine("[green]Ready![/]");
api.csMinimal API
#:sdk Microsoft.NET.Sdk.Web

var app = WebApplication.Create(args);
app.MapGet("/", () => "Hello API");
app.Run();
03

對 AI 而言，C# 突然變得更有吸引力。

不是因為它會取代 Python，而是因為它開始補上「臨時生成、立即執行」這個缺口。

AI Agent 需要的，往往不是一個大型專案，而是一個可靠、可驗證、可以立刻執行的小工具。

C# 的強型別、編譯檢查、企業整合能力與既有 .NET 生態，在單檔執行模式下，第一次真正具備了「腳本型工具」的可用性。它特別適合 JSON、CSV、HTTP API、Windows 自動化與企業內部系統整合。
