C# after the project file

C#，終於可以從一個檔案開始。

.NET 10 少掉的不是一個專案檔，而是一道讓很多人懶得開始的門檻。

我第一次看到這個功能時，想到的不是教學，而是那些原本會用 Python 隨手寫掉的小工具。C# 終於也能進入那個位置。

一個小改動，改的是使用習慣

過去要寫一小段 C#，你通常先建立專案、看見資料夾、處理專案檔。這些步驟沒有錯，只是對一個五分鐘就能寫完的工具來說，顯得太正式。

.NET 10 的 File-based Apps 把這段儀式拿掉了。你可以直接建立 hello.cs，寫下一行程式，再用 dotnet hello.cs 執行。

它仍然是編譯過的 .NET 程式，不是把 C# 變成另一種 Python。差別在於，使用者不必先感受到「我正在開一個專案」。這件事比語法本身更重要。

真正的改變不是「少打一個指令」，而是 C# 開始適合那些不值得建立專案的工作。
01

先跑起來，再決定要不要長大

這是最像腳本語言的地方：你不必先想完整。先做一個檔案，確認它有用，再決定是否升級成正式專案。

安裝 SDK

確認電腦使用 .NET 10 SDK。

建立檔案

新增 hello.cs，直接寫頂層陳述式。

執行

輸入 dotnet hello.cs。

hello.csC#
Console.WriteLine("Hello from C# File-based Apps!");
TerminalBash
dotnet hello.cs
# Hello from C# File-based Apps!
02

它不是只有 Hello World

單檔並不等於玩具。NuGet、Web SDK、命令列參數都能進來，而且保留 C# 原本的型別與工具鏈。

直接引用 NuGet

把套件宣告放在檔案頂端。對一次性工具來說，這比準備一個完整專案更合比例。

console.csC#
#:package Spectre.Console@*
using Spectre.Console;

AnsiConsole.MarkupLine("[green]Ready![/]");

單檔 Web API

需要 HTTP endpoint 時，也可以直接指定 Web SDK。

api.csC#
#:sdk Microsoft.NET.Sdk.Web

var app = WebApplication.Create(args);
app.MapGet("/", () => "Hello API");
app.Run();
03

這可能是 AI Agent 最實用的 C# 入口

Agent 常常只需要生成一個小工具：讀 JSON、整理 CSV、打一個 API、重用公司既有的 .NET 類別庫。這些工作不需要一個宏大的專案。

它適合的工作

  • 資料轉換與批次處理
  • CLI 與一次性維運工具
  • REST API 整合
  • 企業內部 .NET 系統周邊工具

它不會取代 Python

Notebook、資料科學、PyTorch 與龐大的研究生態，仍然是 Python 的主場。C# 的優勢比較明確：既有 .NET 系統、強型別與企業整合。
