C# File-based Apps

C#，現在也能像 Python 一樣直接執行。

從 .NET 10 開始，一個 .cs 檔案就能成為完整應用程式。沒有繁複專案結構，只有更直接的思考、撰寫與執行。

只要一個檔案不必先建立 .csproj

適合快速實驗CLI、自動化、API 與 AI Agent

查看 GitHub 原始碼
01 · Quick Start

三個步驟，從空白檔案到可執行程式。

最小範例

建立 hello.cs，放入一行程式碼，然後直接執行。

Console.WriteLine("Hello from C# File-based Apps! 🚀");

$ dotnet hello.cs
Hello from C# File-based Apps! 🚀

安裝 .NET 10 SDK

確認 dotnet --version 顯示 10.x。

建立 .cs 檔案

直接使用頂層陳述式，不必先建立專案。

執行

使用 dotnet app.cs 或 dotnet run app.cs。

「它看起來像腳本，但本質上仍是一個完整編譯的 .NET 應用程式。」
02 · Examples

不只是 Hello World，而是一種新的 C# 工作方式。

Command Line

命令列參數

接收參數，快速寫出一次性工具。

var name = args.Length > 0
  ? args[0]
  : "World";

Console.WriteLine($"Hello, {name}!");
NuGet

直接引用套件

使用檔案指令加入 NuGet 套件。

#:package Spectre.Console@*

using Spectre.Console;
AnsiConsole.MarkupLine("[green]Ready![/]");
Web API

單檔 Minimal API

即使是 Web API，也能從單檔開始。

#:sdk Microsoft.NET.Sdk.Web

var app = WebApplication.Create(args);
app.MapGet("/", () => "Hello API");
app.Run();
03 · AI & Automation

為什麼這種模式特別適合 AI Agent？

  • 單檔生成與執行，降低專案樣板成本。
  • 強型別與編譯檢查，較容易發現生成錯誤。
  • 可以直接重用既有 .NET 類別庫。
  • 適合 JSON、CSV、HTTP API 與企業系統整合。
  • 原型成熟後，可自然升級成正式專案。

它不是傳統的 .csx

官方名稱是 File-based Apps。它保留了腳本般的使用體驗，同時仍享有編譯、型別系統與完整 .NET 生態。

Python 在 Notebook、資料科學與 PyTorch 仍具優勢；C# 則更適合企業自動化、API 整合與既有 .NET 環境。
